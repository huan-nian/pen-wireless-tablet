# Pen 无线手写板

把 Android 平板 / 手机当作电脑的**无线手写板**：平板用触控笔书写，笔迹以真正的
Windows 笔输入（Windows Ink）注入到电脑上，Photoshop、OneNote、Whiteboard、
Krita 等任何支持压感的软件都能直接画，无需装驱动、无需数据线。

```
┌─────────────────────────┐         UDP 36 字节/包        ┌──────────────────────────┐
│  Android 平板            │  ───────────────────────▶    │  Windows 电脑             │
│  PenCanvasView 采集       │      悬停/按下/移动/抬起       │  UdpPenReceiver 监听       │
│  坐标·压力·倾斜·橡皮       │  ◀───────────────────────    │  PenInjector 注入笔输入    │
│  整块屏幕 = 电脑主屏       │        探测 / 回复（自动发现）  │  整块主屏 = 平板坐标         │
└─────────────────────────┘                              └──────────────────────────┘
```

## 仓库结构

| 目录 | 平台 | 技术栈 | 职责 |
| --- | --- | --- | --- |
| `PenClient/` | Android | Kotlin + Gradle（AGP 9.2.1，minSdk 26 / targetSdk 36） | 采集触控笔事件、打包发送、扫描接收端 |
| `PenCore/` | Windows | C# / .NET 8 类库 | 协议解析、笔注入、UDP 监听、卡笔兜底（两端共用） |
| `PenReceiver/` | Windows | C# / .NET 8 WinForms（需管理员） | 托盘界面：端口、显示器、映射方式、实时统计 |
| `PenReceiver.SelfTest/` | Windows | C# / .NET 8 控制台（**不需要管理员**） | 自检：协议、坐标映射、压力缩放、长按状态机、UDP 收发 |
| `PenProbe/` | Windows | C# / .NET 8 控制台（需管理员） | 排查工具：探测注入能力、向画图注入一笔并截图对比 |

核心逻辑单独放在 `PenCore` 而不是塞进 `PenReceiver`，是因为接收端必须声明管理员权限
（见下文），而自检必须能在没有管理员的环境里跑——两者分成两个 exe 才能做到。

## 快速开始

### 1. 电脑端：启动接收端

```powershell
.\launch-receiver.cmd
```

脚本会自我提权（弹一次 UAC）并启动接收端。窗口里能看到：

- **本机地址** —— 就是平板要填的 IP；
- **目标显示器 / 映射方式** —— 默认主屏 + 铺满整屏；
- **运行状态 / 数据速率 / 链路质量 / 笔状态** —— 实时刷新。

首次运行请在 Windows 防火墙提示里允许该程序的**专用网络**访问（UDP 入站）。

> **为什么必须提权**：Windows 的笔输入注入接口
> （`Windows.UI.Input.Preview.Injection.InputInjector`）只在提升后的进程里可用，
> 普通权限调用 `TryCreate()` 直接返回失败。这不是本项目的限制，是系统设计。

### 2. 平板端：安装并连接

```powershell
cd PenClient
.\gradlew.bat :app:installDebug
```

或者用 Android Studio 打开 `PenClient/` 直接运行。安装后：

1. 打开 App。若上面那个窗口里的 IP 是 `192.168.1.107`，直接填进「电脑 IP 地址」。
2. 懒得记 IP 就点 **「扫描电脑」**：平板会广播探测报文，接收端自动回复，
   发现的地址会直接填进输入框。
3. 点 **「连接」**，状态栏变绿即可书写。
4. 点一下标题栏可以把配置面板收起来，让画布铺满全屏。

**书写约定**：整块画布等比映射到电脑主屏，指哪写哪；手指触摸会被完全忽略
（避免手掌误触）；笔尖离屏约一厘米内就开始上报位置，电脑上会提前出现笔光标。
**笔尖按住不动约 0.6 秒即为长按，松开后电脑上弹出右键菜单**（掌心会轻震一下提示）。

### 3. 先验证再排查

怀疑链路有问题时先跑自检，它不需要管理员权限、不注入任何输入：

```powershell
.\selftest.cmd
```

全部通过时退出码为 0，覆盖协议字节序、坐标映射（铺满 / 等比两种模式）、
UDP 收发计数、丢包统计、探测与回复。

## 通信协议

UDP 单播，全部**小端序**。三种报文用 `magic` 区分：

| 报文 | magic | 长度 | 用途 |
| --- | --- | --- | --- |
| `PEN` | `0x504E4232`（`PNB2`） | 36 字节 | 笔事件 |
| `HELLO` | `0x504E4230`（`PNB0`） | 8 字节 | 平板广播探测接收端 |
| `REPLY` | `0x504E4231`（`PNB1`） | 12 字节 | 接收端回复自己的监听端口 |

`PEN` 报文布局：

| 偏移 | 类型 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | uint32 | `magic` | 固定 `0x504E4232`，不匹配直接丢弃 |
| 4 | uint32 | `seq` | 单调递增序号，接收端据此统计丢包 |
| 8 | int32 | `action` | `0` 按下 / `1` 移动 / `2` 抬起 / `3` 悬停 |
| 12 | float | `x` | 归一化 `[0,1]`，相对采集控件宽度 |
| 16 | float | `y` | 归一化 `[0,1]`，相对采集控件高度 |
| 20 | float | `pressure` | 压力 `[0,1]`，Windows 端按**实测上界**缩放 |
| 24 | float | `tiltX` | 相对屏幕 X 轴倾角，度 |
| 28 | float | `tiltY` | 相对屏幕 Y 轴倾角，度 |
| 32 | int32 | `flags` | 位 0 = 笔尾橡皮，位 1 = 长按（= 右键） |

Android 只提供「笔身与屏幕法线夹角 + 倾斜方向」，Windows 要的是分别相对 X/Y 轴的
倾角，因此平板侧做了一次球面分解（`PenProtocol.kt` 的 `tiltToWindows`）。

端口默认 **8888**，两端都可改（Android 端在界面上，Windows 端在窗口里）。

## 实测得到的三条硬约束

下面三条都是在本机实测出来的，都推翻了「照文档写就行」的直觉。改代码前值得先看一眼：

**1. 压感的有效范围取决于当前生效的笔设备，不能写死 0..1023。**

实测：压力 `0` 和 `1` 被接受，`2` 及以上一律被 `InjectPenInput` 整包拒绝，抛
`ArgumentException: Value does not fall within the expected range`。

关键在于它拒绝的是**整个报文**而不是「忽略压力」——所以只要压力超出范围，
这一笔就完全不会出现，表现为「平板上写得出来、电脑上毫无反应」。
因此 `PenInjector` 构造时会实测一次上界，并在界面上报告结果；压力换算成整数时，
上界为 1 的情况用**阈值**而不是四舍五入（否则 0.5 会被舍成 0，等于没有压感）。

**2. 注入的笔输入不会触发 Windows 的长按右键手势。**

实测：笔按下后原地静止 1.1 秒再抬起，目标窗口收到的右键次数是 **0**。
所以「长按 = 右键」不能指望系统识别，必须由平板端判定（静止 600ms 且位移不超阈值），
在抬起报文上打标记，由接收端显式注入鼠标右键；这一笔的笔迹要整体丢弃，
否则长按时会先留下一个墨点。

**3. 鼠标右键注入用的是 0..65535 归一化坐标，不是像素。**

传像素会让光标落在完全错误的位置（实测传 `480` 结果落在 `14`）。归一化基准用虚拟屏。

## 相比上一版修掉的问题

上一版能跑通 demo，但在真实书写场景下有几个会直接毁掉体验的问题：

| 问题 | 原因 | 现在的做法 |
| --- | --- | --- |
| 高刷笔下延迟越写越大 | 发送端用无界 `Executor` 排队，接收端每个报文打印一行控制台日志 | 发送端改有界队列（满时丢**最旧**的移动事件，保住最新位置）；接收端只在界面上做限流刷新，热路径零日志 |
| 抬笔报文一丢，笔尖永久卡在按下状态 | UDP 不可靠，且没有兜底 | 接收端看门狗：400ms 没收到任何笔报文就主动补一次抬起，界面显示「兜底抬笔」次数 |
| 高 DPI 屏幕上笔迹整体偏移 | 注入坐标必须是物理像素，进程没声明 DPI 感知时 `Screen.Bounds` 返回逻辑像素 | 项目级 `ApplicationHighDpiMode=PerMonitorV2`，并保留 `Application.SetHighDpiMode` |
| 每次换网络都要改代码里的 IP | `serverIp` 硬编码在 Kotlin 里 | 界面上填写 + SharedPreferences 持久化 + 局域网自动扫描发现 |
| 换台电脑就要重编译 | 同上 | 同上；「扫描电脑」一键填地址 |
| 手指触摸会干扰书写 | 只判断了 pointer 0 的工具类型 | 遍历事件里真实指针的工具类型，手指事件直接放行不消费 |
| 笔尖离开屏幕前看不到光标 | 没处理悬停事件 | `onGenericMotionEvent` 上报悬停，Windows 侧以 `InRange` 注入，落笔前就有光标 |
| 倾斜数据发了但没用上 | 接收端把 tilt 丢弃 | 完整换算成 `TiltX`/`TiltY` 注入（画笔的侧锋效果） |
| 笔尾橡皮无法使用 | 没有识别 | 识别 `TOOL_TYPE_ERASER`，注入 `Inverted \| Eraser` 按钮 |
| 等比映射时最大坐标损失、留边不对称 | 按屏幕**宽度**缩放，右边缘多出半像素 | 改用像素跨度 `[left, right-1]` 计算，1:1 对应像素 |
| 退出后鼠标被「按住」 | 异常路径没有清理 | 视图销毁 / 窗口关闭 / 进程退出都强制抬笔并 `UninitializePenInjection` |
| **彻底画不出来（每次注入都被拒绝）** | 压力固定缩放到 `0..1023`，而本机只接受 `0..1`，于是每个报文都被 `InjectPenInput` 拒绝 | 构造时实测压力上界并据此缩放；上界为 1 时改用阈值判定；界面上报告压感能力 |
| 长按平板不会有右键菜单 | 注入的笔输入不触发系统长按手势 | 平板端自判长按（600ms 静止），抬起报文打标记，接收端先解笔再注入鼠标右键，并丢弃这一笔的笔迹 |
| 重复双击启动器后进程越积越多、抢 8888 端口 | 提权进程普通权限杀不掉 | 加单实例锁；重复启动改为广播消息把已有窗口唤到前台 |
| 启动脚本双击一闪而过 | 文件被保存成 LF 行尾，`cmd.exe` 解析错乱 | 两个 `.cmd` 统一为 CRLF；`.ps1` 统一为带 BOM 的 UTF-8（否则 PowerShell 5.1 中文乱码） |

## 已知限制

- **本机没有真实笔数字化器，因此拿不到压感**。接收端启动时会实测压力上界并在界面上
  报告（本机测得为 1，即只能表达「有/无压力」）。要获得真正的粗细变化，需要一台
  Windows 能识别为笔设备的数字化屏；此时上界会是 1023，代码会自动用上。
- **平板必须有真正的压感笔**。手指、普通电容笔都不行：本项目只采集
  `TOOL_TYPE_STYLUS` / `TOOL_TYPE_ERASER`。不少平板的笔也只在 0/1 两档上报压力。
- **只映射整块主屏**。没有做「映射到指定窗口 / 指定区域」，也没有做坐标校准
  （旋转、非等比拉伸、边缘偏移）。等比模式可以缓解长宽比不一致导致的笔迹变形。
- **平板锁定横屏**。竖屏书写没有做旋转映射。
- **长按 = 右键是平板端判定的**：静止 600ms 且位移不超过阈值。所以「按住笔停顿一下」
  就会弹右键菜单，而不是在电脑上画一个点——这是有意为之、也是你要求的行为。
- **单指单笔**：只跟一支笔，不处理多笔同时书写。
- **局域网明文**：报文没有任何加密或鉴权。同网段的设备可以伪造笔输入，
  所以接收端提供了「只接受指定平板地址」的来源限制开关，建议开启。
- **注入的是笔事件而不是鼠标事件**，所以不支持把平板当普通鼠标用。
- 笔身按键（barrel button）没有映射。

## 运行环境

- Windows 10 1809 及以上（笔注入接口要求 `10.0.19041` 及以上的目标框架）。
- 电脑端需要 .NET 8 SDK：`dotnet --version` 能输出版本号。
- 平板 Android 8.0（API 26）及以上，且与电脑在同一局域网。
- Windows 防火墙需放行 UDP 8888 入站。

## 手工构建与排查

```powershell
# Windows 端（类库 + 接收端 + 自检 + 探针）
dotnet build PenCore\PenCore.csproj
dotnet build PenReceiver\PenReceiver.csproj
dotnet build PenReceiver.SelfTest\PenReceiver.SelfTest.csproj
dotnet build PenProbe\PenProbe.csproj

# Android 端
cd PenClient
.\gradlew.bat :app:assembleDebug      # 产物在 app\build\outputs\apk\debug\
.\gradlew.bat :app:installDebug       # 直接装到已连接的平板
```

> Android 端构建需要 JDK 17 以上。若命令行里 `java -version` 还是 Java 8，
> 把 `JAVA_HOME` 指向 Android Studio 自带的 JBR，例如：
> `$env:JAVA_HOME = 'E:\Applications\Android Studio\jbr'`

### 三层排查手段

从「不碰笔」到「接近真实书写」，按代价从低到高：

1. **`selftest.cmd`**（不需要管理员）：53 项断言，覆盖协议字节序、两种映射模式、
   压力缩放、长按状态机、UDP 收发与探测回复。
2. **接收端界面**：
   - 「暂停注入」——仍然统计报文但不注入，用来区分「网络不通」和「注入失败」；
   - 「注入权限」——显示「正常（已成功注入）」即说明提权成功；
   - 「数据速率 / 丢包 / 断序 / 兜底抬笔」——直接看出链路哪一段有问题。
3. **`PenProbe.exe`**（需要管理员，会短暂接管屏幕）：绕过平板与 UDP，直接用接收端
   同一份注入代码验证「注入到底行不行」。它会把 Windows 画图打开、注入一条曲线、
   截图对比前后差异，并打印实测到的压力上界。

   这条路径能把问题干净地切成两半：**探针能画出线 → 问题在平板或网络；画不出 → 问题在注入**。

```powershell
dotnet run --project PenProbe    # 会自动提权（UAC）
```
